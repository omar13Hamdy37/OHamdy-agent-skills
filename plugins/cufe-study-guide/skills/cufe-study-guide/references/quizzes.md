# End-of-lecture quizzes

Use at the final assessment stage. Include a compact meaningful quiz for every
substantial guide unless the user opts out; include one for a smaller scope when
requested or useful. A tiny fragment need not acquire a disproportionate quiz.
In-section checkpoints and exercises have different purposes and do not replace
the final quiz for a substantial guide.

## Choose mode and size independently

Interpret natural language: “give me situations” suggests scenario-heavy;
“trace the code” suggests code-tracing; “exam tomorrow” suggests essential exam-style
practice but does not establish a real exam format. Honor an explicit mode, size,
or quiz waiver. If the requested mode cannot meaningfully test the supplied content,
adapt to the closest useful form and explain the limitation briefly.

| Mode | Question design |
| --- | --- |
| **Conceptual** | Ask why/how, predict a change, or explain a relationship using the taught model. |
| **Scenario-heavy** | Give a short realistic situation; ask which concept/method applies and why. |
| **Terminology** | Test meaning, distinctions, and appropriate use in context rather than only word recall. |
| **Exam-style** | Use supplied exercise/past-exam style if available; otherwise create course-aligned practice without claiming to predict the exam. |
| **Code-tracing** | Specify language/engine assumptions, inputs, and relevant state; ask for output or decisive execution steps. |
| **Calculation-heavy** | Provide sufficient values, units, and conditions; ask for method, calculation, and interpretation. |
| **Mixed** | Combine a small set of forms suited to the lecture, emphasizing application and explanation. |

Default to mixed questions suited to the subject. As rough starting points, use
4–6 questions for a short/simple lecture, 6–10 for a normal lecture, and somewhat
more for a very dense lecture only when the extra questions add coverage. These
are planning ranges, not quotas. A requested small quiz or a narrow scope can
need fewer. Avoid hiding a large exam in dozens of multipart subquestions.

## Build a compact coverage plan

1. Select essential nodes, relationships, methods, and high-risk misconceptions
   from the concept map/coverage ledger. Prioritize transferable understanding.
2. Assign each question a learning target and difficulty appropriate to the guide.
   Mix direct application with a modest new case; do not require untaught enrichment.
3. Ensure important groups get reasonable representation. One well-designed
   scenario can cover a relationship plus a method without duplicating questions.
4. Draft the solution while drafting the question. Remove ambiguous wording,
   unsupported assumptions, accidental answer cues, or dependencies on a hidden answer.

Most questions should require reasoning/application; a few important terminology
checks are fine. Optional enrichment should not dominate or become an unannounced
exam requirement. Use explicit “optional challenge” scope if such a question earns
its place. Preserve enough instruction in the guide that the quiz is answerable.

For multiple-choice questions, make wrong options plausible misconceptions, use
consistent assumptions, and ensure one supported answer unless multiple selection
is explicit. Avoid joke options and distractors wrong only because of hidden
technicalities. Free-response questions can accept equivalent valid reasoning.

## Keep the Answer Key separate

Place all questions first, then a distinct **Answer Key** after them. Do not print
the answer beneath each final-quiz question or put it in a hint that gives it away.
Include matching question IDs so readers can find feedback easily.

Each answer gives the correct result, decisive reasoning/steps, and a relevant
misconception when it helps. For calculations, retain units and assumptions; for
code, trace the state that produces the output; for conceptual questions, accept
equivalent technically correct explanations. Explain why a tempting wrong option
fails when that is the learning point.

Re-solve questions independently of their drafted answers where practical. Check
that the source, guide, and key agree. Correct any mismatch in both places. At
handoff, mark the Answer Key as separated from the quiz so the output mechanism
can keep answers out of immediate view without obscuring access. See
[document-design.md](document-design.md) and
[quality-checklist.md](quality-checklist.md).
